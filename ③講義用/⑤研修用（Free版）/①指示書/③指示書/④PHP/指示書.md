Claude に渡す作業指示書です。

「補足」は引用(>)で示します。


## 指示内容１ 作業フォルダに関する情報

- チャットに以下のファイルを添付する
  - login.html、product_list.html、order_detail.html、style.css、logo.svg、テーブル定義書（myappdb）.sql
- 添付時にファイル名に「_1」などが付いても同じファイルとして扱い、出力するファイル名は元の名前(style.css、logo.svg など)を使うこと
- 生成したプログラムはzipファイルとしてまとめること
- zip には Sample01 フォルダを入れ、その直下に各PHPファイルと src、templates、config を置く(XAMPP の htdocs にそのまま配置できる形)


## 指示内容２ 生成物の条件定義

### (1)以下の内容でPHPアプリを生成すること
- 素のPHP(フレームワーク・Composer は使わない)のWebアプリ
  - 開発環境：`XAMPP(Apache 2.4, PHP 8.4.28)`
  - 本番環境：`AWS 上の Apache 2.4 + PHP 8.4.28`
  - プロジェクト名："Sample01"
  - `DBMS:PostgreSQL 18.4`
- PHP 8.4 で動作する構文を使う(8.5 以降専用の機能は使わない)

### (2)プロジェクトの構成
- ディレクトリ構成は以下のとおりにする

```
Sample01/
├─ index.php          (ウェルカムページ。login.php へリダイレクト)
├─ login.php
├─ products.php
├─ orders.php
├─ logout.php
├─ style.css
├─ logo.svg
├─ src/               (共通処理: Db.php、Auth.php など)
│   └─ .htaccess
├─ templates/         (画面テンプレート: login.php、product_list.php、order_detail.php)
│   └─ .htaccess
└─ config/
    ├─ db.ini
    └─ .htaccess
```

- src、templates、config の各フォルダには、外部からのアクセスを拒否する `.htaccess` を置く
  - 内容：`Require all denied`(Apache 2.4 の書式)
- 全ファイルの先頭に `declare(strict_types=1);` を付ける
- DB 接続には PDO(pdo_pgsql 拡張)を使う。mysqli や pg_* 関数は使わない
- PDO は `ERRMODE_EXCEPTION` を指定し、エミュレートプリペアは無効(`ATTR_EMULATE_PREPARES => false`)にする
- db.ini は config に置き、`parse_ini_file()` で読み込む
- 画面テンプレートは templates 配下に置き、直下のスクリプト(login.php など)から `require` してのみ表示する(テンプレートへ直接アクセスさせない)
- 画面に出力する値はすべて `htmlspecialchars($v, ENT_QUOTES, 'UTF-8')` でエスケープする(ヘルパー関数 `h()` を用意して使う)
- style.css と logo.svg は Sample01 直下に置く(元のファイルをそのままコピーする)
- リンクとリダイレクトは相対パスで記述する(例：`header('Location: products.php');`)。ホスト名・ポート番号・フォルダ名(/Sample01/)をコードに直書きしない
- リクエストとレスポンスの文字コードは UTF-8 とする(`header('Content-Type: text/html; charset=UTF-8');`)
- リダイレクトの後は必ず `exit;` を呼ぶ

> **補足**  
> .htaccess が効くには、Apache 側で当該フォルダの AllowOverride が有効である必要がある。  
> XAMPP の標準設定では有効。AWS の Apache では設定を確認する(フェーズ②の手順書で案内)。  
> pdo_pgsql 拡張が無効だと接続できない。php.ini(XAMPP では xampp/php/php.ini)で `extension=pdo_pgsql` の行の先頭の「;」が外れているか確認する  

### (3)画面の URL(スクリプトのマッピング)
- GET /Sample01/login.php … ログイン画面を表示、POST /Sample01/login.php … ログイン認証(ウェルカムページ /Sample01/(index.php)も login.php へ転送)
- GET /Sample01/products.php … 商品一覧画面
- GET /Sample01/orders.php?code=商品コード … 注文情報詳細画面
- POST /Sample01/logout.php … セッションを破棄し login.php へリダイレクト
- ログイン中かどうかはセッション変数 `$_SESSION['loginUser']` の有無で判定する
- ログイン成功時は `session_regenerate_id(true)` を呼んでからセッションに保存する
- logout.php は POST 以外のリクエストの場合、login.php へリダイレクトするだけで何もしない
- 以降の説明では、URL の「/Sample01/」を省略して記載する


## 指示内容３ DB接続情報

### (4)DBの接続情報は設定ファイル(config/db.ini)を利用すること
- db.ini に記録する内容

```ini
db.host=localhost
db.port=5432
db.name=myappdb
db.user=myapp
db.password=1234
```

- DSN は `pgsql:host=…;port=…;dbname=…` の形式で組み立てる(文字コードは UTF-8 を指定する)

> **補足**  
> config フォルダは .htaccess で外部アクセスを拒否している。  
> ただし db.password は AWS へデプロイする前に書き換える(フェーズ②の手順書で案内)。  
> 本番では db.ini を DocumentRoot の外へ移す方法もある(フェーズ②で案内)  

### (5)テーブル定義と初期データは以下の SQL ファイルを参照
- テーブル定義書（myappdb）.sql
- DDL(CREATE TABLE)と初期データ(INSERT)が書かれている。テーブル名・列名・型・主キーはこのファイルのとおりにする
- プログラムからはテーブルの作成・データ投入・削除(DDL/DML)を実行しない。データの読み取り(SELECT)だけを行う
- [廃番商品]テーブルは本アプリでは使わない

> **補足**  
> このSQLは各テーブルを DROP TABLE … CASCADE で削除して作り直す。実行するとデータが初期化されるため、研修用DB(myappdb)以外では実行しない。  
> アプリを動かす前に、DB で実行してテーブルと初期データを作っておく(A5M2 など)  


## 指示内容４ ログイン画面

### (1)以下の内容で「ログイン画面」を生成すること
- 画面レイアウトは以下に準拠
  - `login.html`
  - login.htmlから参照されるファイルも参照すること

### (2)ログイン時の認証を組み込む

### (2-1)ログイン認証用アイテム
- ”ユーザ名”
  - ”パスワード”

### (2-2)ログイン時の認証方法
- [ユーザー情報]テーブルの値との一致を認証する
  - ”ユーザ名”：[ユーザー情報].eメール と値が一致すること
  - ”パスワード”：入力値を UTF-8 のバイト列にして SHA-256 でハッシュ化し、小文字16進数64桁の文字列にしたものが [ユーザー情報].パスワード と一致すること(ソルトなし)
- ハッシュ化には `hash('sha256', $password)` を使う(戻り値は小文字16進数64桁)
- ハッシュ値の比較には `hash_equals()` を使う
- SQL の値は PDO のプリペアドステートメント(`prepare` + プレースホルダ ? または :name)で渡す
- 入力値が未送信(null)の場合は空文字として扱い、認証失敗とする

> **補足**  
> 確認用ユーザーはテーブル定義書(sql)の初期データで登録済み。  
> ユーザ名:user@example.com  
> パスワード:1234(DB には SHA-256 のハッシュ値が入っている)  

### (2-3)ログイン認証に成功：
- 「商品一覧画面」(products.php)へリダイレクト

### (2-4)ログイン認証に失敗：
- 再度ログイン画面を表示

> **補足**  
> ログイン認証失敗時には以下のメッセージをメッセージエリアに表示(html に準拠)  
> 「ユーザ名またはパスワードが正しくありません。」  


## 指示内容５ 商品一覧画面

### (1)「商品一覧画面」の生成
- 画面レイアウトは以下に準拠
  - `product_list.html`
  - product_list.htmlから参照されるファイルも参照すること

### (2)ログイン認証を経由せずに「商品一覧画面」へ遷移した場合：
- 「ログイン画面」へリダイレクト

### (3)ログアウトボタン
- html に合わせ POST /logout.php で「商品一覧画面」からログアウトし「ログイン画面」へ遷移する

### (4)「商品一覧情報」の生成
- [商品テーブル]と[注文テーブル]を取り込む

### (4-1)[商品テーブル]は全件取り込む

### (4-2)[商品テーブル]は[注文テーブル]とLEFT JOINする(結合キー：”商品コード”）

### (5)「商品一覧画面」への情報セット

### (5-1)(4)で生成した「商品一覧情報」から画面に表示する項目をすべてセットする
- ”商品コード”の昇順で表示
- ”注文状況”には、[注文テーブル]に情報が存在する商品について ”注文日”と”注文番号”の組の種類数を”件数”として「注文(n 件)」の形式で表示する
- 件数は次の式で数える(注文が無い商品は 0 件になる)
  - `COUNT(DISTINCT (o.注文日, o.注文番号)) FILTER (WHERE o.注文番号 IS NOT NULL)`
- 件数が 0 件の商品は「注文なし」と表示する
- 各カラムの表示形式は html に準拠する
- 取得した行はテンプレート内で `foreach` を使って表示する

> **補足**  
> 主キーに注文日が含まれ、別の日に同じ注文番号があり得るため、注文日と注文番号の組で数える  
> LEFT JOIN で注文が無い商品は (NULL, NULL) の組になり、FILTER を付けないと 1 件と数えられてしまう  
> PDO で取得した COUNT の値は int ではなく文字列で返ることがあるため、`(int)` にキャストして比較する  

### (5-2)”注文状況”のカラムには「注文情報詳細画面」(orders.php?code=商品コード)へのリンクを張る
- リンクの code の値は `urlencode()`(または `http_build_query()`)でエンコードし、さらに `h()` でエスケープする
- ”注文”情報が存在しない”商品”の”注文状況”は「注文なし」と表示しリンクは張らない(html に準拠)
- ”関連商品コード”が無い場合は「―」と表示する(html に準拠)

## 指示内容７ 動作確認

### (1)生成後に以下の手順で起動できるようにすること
- zip を展開し、Sample01 フォルダを XAMPP の htdocs(例：`C:\xampp\htdocs\`)の直下に置く
  - 配置後のパス：`C:\xampp\htdocs\Sample01\login.php`
- XAMPP コントロールパネルで Apache を起動する
- config/db.ini の接続情報がローカルの DB と合っているか確認する
- http://localhost/Sample01/login.php を開く

> **補足**  
> XAMPP の Apache は標準でポート 80 を使うため、URL にポート番号は付かない。  
> 画面が真っ白、または DB 接続エラーになる場合は、php.ini で pdo_pgsql が有効か確認し、変更後は Apache を再起動する。  
> PostgreSQL は XAMPP に含まれないため、別途インストール・起動しておく
